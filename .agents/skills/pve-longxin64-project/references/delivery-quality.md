## 18. 测试策略

### 18.1 单元测试

- 领域状态机和权限规则。
- 模板版本不可变约束。
- 幂等键、批量拆分、锁和重试决策。
- PVE 错误归一化和能力检测。
- Broker 分配和连接授权。

### 18.2 集成测试

- 使用可编程 Fake PVE Server 覆盖成功、超时、权限错误和 UPID 恢复。
- PostgreSQL 迁移、事务、任务租约和 Worker 崩溃恢复。
- API Token、TLS 内部 CA 和凭据加密。
- SSE 断线重连和事件顺序。

### 18.3 端到端测试

- 集群接入到资源同步。
- 模板导入、桌面池创建和批量克隆。
- 课前检查、整班开机、学生连接和下课收机。
- 快照、回滚、重建和只重试失败项。
- 模板金丝雀、发布、灰度更新和失败停止。
- 越权、重复提交、页面刷新和 Worker 重启。

### 18.4 实验室验证

高风险 PVE 操作必须在隔离测试集群验证：

- 节点离线。
- PVE API 短时断线。
- 存储空间不足。
- 克隆或快照部分失败。
- Worker 在收到 UPID 后崩溃。
- 终端离线或连接票据过期。
- 50 台桌面分波次启动。
- LoongArch64 瘦客户机的 FreeRDP、浏览器和 Agent 兼容性。

## 19. 实施路线图

### Phase 0：决策与工程基础

- 确认 PVE 版本、集群规模、存储、网络和瘦客户机硬件。
- 用 ADR 固化后端、数据库、远程协议和认证选择。
- 建立 Go、React、OpenAPI、迁移、测试和 CI 骨架。
- 建立 Fake PVE Server 和安全配置加载。

退出标准：本地可启动 Web、API、Worker 和 PostgreSQL，CI 能执行测试与静态检查。

### Phase 1：PVE 接入与只读资源

- 集群凭据和 TLS 信任。
- PVE Adapter、能力检测和资源同步。
- 节点、存储、网络、模板和 VM 只读页面。
- 基础认证、管理员角色和审计。

退出标准：平台能安全接入测试 PVE，准确展示资源与同步健康。

### Phase 2：单桌面生命周期与任务引擎

- Operation、OperationItem、幂等键、锁、Worker 和 SSE。
- 单 VM 开机、优雅关机、强制停止、重启、克隆、快照和回滚。
- UPID 持久化、重启恢复、错误归一化和单项重试。

退出标准：Worker 中断后可继续跟踪任务，重复请求不重复执行。

### Phase 3：云教室与批量工作流

- Classroom、Seat、DesktopPool、VirtualDesktop。
- 批量克隆、分波次开机、课前检查和下课收机。
- 教师课堂控制台、任务抽屉和部分失败处理。
- RECREATE、ROLLBACK_BASELINE、PERSISTENT 三种策略。

退出标准：能从模板创建参考规模教室，并完成完整上课与收机流程。

### Phase 4：瘦客户机与远程桌面

- 设备一次性注册、证书、心跳和座位绑定。
- Desktop Broker 和短期连接票据。
- FreeRDP 或 Guacamole 路径。
- noVNC 管理员应急控制台。
- Launcher 全屏、断线重连和会话撤销。

退出标准：学生终端无法接触 PVE Token，并能稳定连接被分配桌面。

### Phase 5：模板版本与更新

- TemplateVersion 状态机、维护 VM、验证和发布。
- 金丝雀桌面、UpdateCampaign、分批更新和失败暂停。
- 基线快照、保留策略和漂移检测。

退出标准：新模板发布不改变既有课程，失败金丝雀不会扩散。

### Phase 6：强化与交付

- OIDC/LDAP/AD、MFA 和更细 RBAC。
- 完整监控、告警、备份和运维手册。
- 安装向导、升级方案和兼容矩阵。
- 压力、故障注入、安全和可访问性测试。
- LoongArch64 终端构建与真实硬件验收。

退出标准：满足上线安全、稳定性、可恢复性和运维要求。

## 20. MVP 验收标准

- 从一个模板批量创建至少 50 台学生桌面，每台都有明确终态。
- 教师提交批量操作后 1 秒级获得任务 ID；耗时操作不阻塞 HTTP。
- 重复提交同一个请求不会创建重复 VM、快照或任务。
- Worker 在克隆、启动或回滚期间重启后，能根据已保存 UPID 恢复跟踪。
- 50 台桌面分波次启动时，控制平面仍可响应，并发数可配置。
- PVE 短时断线后能恢复对账，不盲目重放，不把未知状态报告为成功。
- 学生只能连接分配给自己的桌面。
- 终端和浏览器中不存在 PVE Token。
- 课程关闭或授权撤销后，远程桌面连接授权立即失效。
- 新模板版本不会修改既有课程绑定，失败金丝雀不能正式发布。
- RECREATE 或快照回滚不会删除标记为持久化的数据盘。
- 所有删除、回滚、强制停止、模板发布和远程控制都有审计事件。
- 存储或内存不足时，在大规模操作前明确拒绝或降低批次。
- 节点故障、部分克隆失败或终端离线不会阻塞其他可用座位。
- 教师无需进入 PVE 基础设施页面即可完成课前检查、开课和收机。
- 刷新页面后仍可追踪批量任务，并能只重试失败项。

## 23. Definition of Done

一个功能只有同时满足以下条件才算完成：

- 业务行为和权限边界明确。
- API 契约和错误语义已更新。
- 异步任务具有幂等、超时、锁、恢复和部分失败处理。
- 危险操作具有预检、确认、审计和影响范围。
- UI 包含加载、空、成功、失败、无权限和陈旧状态。
- 关键路径有单元测试；跨组件路径有集成或端到端测试。
- 日志、指标和审计足以定位问题。
- 不泄露 PVE、设备或学生凭据。
- 文档、部署或运维说明同步更新。
- 通过键盘、减少动态效果和基础可访问性检查。
- 已在 Fake PVE 或隔离实验集群验证，不以模拟结果冒充真实 PVE 成功。

## 24. 开工前必须确认的问题

以下信息会影响实现，但不阻塞项目骨架和 Fake PVE 开发：

1. 目标 PVE 版本、节点数量和是否使用集群。
2. 存储类型、容量、快照和链接克隆能力。
3. 学生 VM 的操作系统、软件、Guest Agent 和许可证。
4. 瘦客户机的具体龙芯型号、LoongArch 版本、内存、显卡和 Linux 发行版。
5. 默认采用 FreeRDP、Guacamole、SPICE 还是组合方案。
6. 是否需要 USB、音频、打印机、剪贴板和文件重定向。
7. 教室规模、同时在线人数和网络带宽。
8. 是否已有 AD、LDAP、OIDC 或校园统一认证。
9. 学生数据使用独立数据盘、网络家目录还是无状态模式。
10. 是否允许教师观察或控制学生屏幕，以及相应隐私制度。

在这些问题确认前，所有相关实现都应保持适配器边界，避免把环境假设写死。
