# 产品、领域模型与课堂工作流

## 目录

- 项目定位、假设与非目标

## 1. 项目定位

PVE-Longxin64 是一个面向学校、培训机构和计算机教室的第三方 Proxmox VE 云教室管理平台。

平台不以复制完整 PVE 管理后台为目标，而是把 PVE 的虚拟化能力组织成教师和学校运维能够直接使用的云教室工作流：

- 管理员维护黄金教学模板及其不可变版本。
- 管理员按教室或课程批量创建学生虚拟桌面。
- 教师能够执行课前检查、整班开机、关机、快照、还原和下课收机。
- 瘦客户机作为学生终端，自动连接当前座位被分配的虚拟桌面。
- 所有批量操作都可追踪、可审计、可重试，并能清楚呈现部分失败。
- 教学镜像能够进行维护、验证、灰度发布、回滚和分批更新。

产品应优先解决“如何稳定地上完一节课”，而不是优先暴露 PVE 的底层概念。

### 1.1 核心价值

1. 一间教室可以在课前快速恢复到已知、可教学的状态。
2. 教师无需理解 PVE 节点、存储和 VMID，也能完成日常课堂操作。
3. 学生从瘦客户机登录后，只能连接分配给自己的桌面。
4. 管理员能维护少量模板，并安全地向大量学生桌面发布更新。
5. 任何批量或破坏性操作都不会成为不可见、不可恢复的黑盒。

### 1.2 初始假设

在获得真实部署环境信息前，按以下假设推进，并通过 ADR 记录后续变更：

- 首先面向学校局域网内的单组织部署。
- MVP 支持一个 PVE 集群，但领域模型保留 organization_id 和 cluster_id。
- 支持 PVE 8/9，实际兼容范围必须通过能力检测和测试矩阵确认。
- PVE 主机架构不因仓库名而预设为龙芯。
- 仓库名中的 Longxin64 暂按“龙芯 LoongArch64 瘦客户机兼容目标”处理。
- 瘦客户机优先采用 LoongArch64 Linux，运行全屏 Launcher 或浏览器 kiosk。
- 教学 VM 应安装 QEMU Guest Agent，并配置可用的远程桌面服务。
- 首先支持局域网场景；公网访问必须经过 VPN、零信任网关或等价安全边界。

### 1.3 非目标

MVP 不包含：

- 替代 PVE 原生后台的所有节点、Ceph、网络和 HA 管理能力。
- 自动跨多个 PVE 集群进行复杂调度。
- SaaS 计费、多租户计费或资源交易。
- GPU/vGPU、高帧率 3D 和专业音视频桌面的完整方案。
- 完整课堂屏幕直播、录制和监控。
- Proxmox Backup Server 灾备编排。
- 瘦客户机高级 OTA；只预留协议和数据模型。
- 通过任意 SSH 命令直接管理 PVE。

## 2. 产品组织方式

界面和领域模型必须以“云教室”而不是“PVE 虚拟机列表”为中心。

~~~text
组织/校区
└── 云教室
    └── 座位
        ├── 瘦客户机
        ├── 学生虚拟桌面
        ├── 当前模板版本
        └── 当前课程、连接和任务
~~~

以下对象必须分开建模：

- **座位 Seat**：教室中的物理或逻辑位置。
- **瘦客户机 ThinClient**：可替换的物理终端设备。
- **虚拟桌面 VirtualDesktop**：可重建、可迁移、可重新分配的 PVE VM。
- **学生或用户 User**：在某个课程场次中使用座位和桌面的人。

不得把 MAC 地址、座位号或 PVE VMID 当作平台全局主键。

## 3. 角色与权限

| 角色 | 主要能力 |
| --- | --- |
| 平台管理员 | 集群接入、凭据、系统策略、用户角色、全部审计 |
| 学校运维 | 教室、模板、桌面池、终端、批量任务和故障处理 |
| 教师 | 被授权教室的课前检查、开课、收机、单机重试和有限远程协助 |
| 学生 | 只查看并连接当前分配给自己的桌面 |
| 审计员 | 只读查看配置、操作记录和安全审计 |

权限规则：

- 权限必须在服务端校验；前端隐藏按钮不能替代授权。
- 权限范围至少支持组织、校区、教室和资源类型。
- 学生不能枚举其他学生、其他桌面或 PVE 基础设施。
- 教师不能默认发布模板、删除桌面池或管理 PVE 凭据。
- 删除、回滚、模板发布、强制停止和远程控制必须使用独立权限。

## 5. 状态来源与对账

平台数据库和 PVE 承担不同职责：

- PVE 是节点、存储、虚拟机电源和任务执行结果的事实来源。
- 平台数据库是教室、座位、课程、模板版本、期望状态、权限和审计的事实来源。

虚拟桌面不能只保存一个 status 字段，至少要区分：

- desired_state：平台希望达到的状态。
- observed_state：最近从 PVE 观察到的状态。
- operation_state：当前平台任务的状态。
- last_reconciled_at：最后对账时间。
- config_hash：期望配置与实际配置的差异。

必须运行周期性 Reconciler：

1. 拉取受管 PVE 资源的实际状态。
2. 对比平台期望状态和资源标记。
3. 更新观察状态和漂移告警。
4. 只在规则明确且安全时自动修复。
5. 未知或孤儿资源只告警，不得自动删除。

## 6. 核心领域模型

- Organization：组织边界；MVP 为单组织。
- User、Role、Permission：身份和权限。
- PveCluster：接入点、版本、证书、凭据引用、能力和健康状态。
- PveNode、Storage、Network：从 PVE 同步的基础设施镜像。
- Classroom：教室、时区、默认网络和策略。
- Seat：教室座位编号与布局。
- ThinClient：设备 UUID、证书、架构、Agent 版本、IP、心跳和在线状态。
- Course、ClassGroup：课程和教学班。
- ClassSession：一次具体上课，包含起止时间、教室、模板版本和结束策略。
- DesktopPool：共享模板、规格、网络和还原策略的一组桌面。
- VirtualDesktop：平台 UUID 与 cluster_id + PVE VMID 的映射。
- DesktopAssignment：在指定时间内连接座位、终端、学生和桌面。
- Template、TemplateVersion：逻辑模板和不可变版本。
- BaselineSnapshot：平台认可、可回滚的基线。
- UpdateCampaign：模板升级目标、批次、暂停点和结果。
- RemoteSession：短期连接授权、协议、网关和撤销状态。
- Operation、OperationItem：批量父任务和单资源子任务。
- AuditEvent：不可变的安全与操作审计。

内部主键使用 UUID。PVE VMID 只在一个 cluster_id 内唯一。

## 7. 核心工作流

### 7.1 接入 PVE 集群

1. 管理员输入 API 地址、证书信任方式和最小权限 Token。
2. 后端校验证书、版本、身份和权限。
3. 检测节点、存储、网络、模板、快照和克隆能力。
4. 只允许选择专用 PVE Pool、存储和网络作为平台管理范围。
5. 保存加密凭据引用，不返回 Token 明文。
6. 创建首次同步任务并展示结果。

浏览器和瘦客户机永远不能直接持有 PVE Token。

### 7.2 模板生命周期

已发布模板不可变，禁止静默覆盖。

~~~text
DRAFT
  → BUILDING
  → VALIDATING
  → PUBLISHED
  → DEPRECATED
  → RETIRED
~~~

构建或验证失败分别进入 BUILD_FAILED 或 VALIDATION_FAILED。

标准更新流程：

1. 从当前版本克隆隔离的维护 VM。
2. 安装系统补丁、课程软件和资源。
3. 执行系统清理；Windows 使用 Sysprep，Linux 清理 machine-id/Cloud-init 状态。
4. 关机并生成新的 PVE 模板 VMID。
5. 创建少量金丝雀桌面。
6. 验证启动、QEMU Guest Agent、网络、远程桌面和关键应用。
7. 发布新的不可变 TemplateVersion。
8. 新课程默认使用新版本；既有课程不被隐式切换。
9. 通过 UpdateCampaign 分波次更新，失败时停止扩散。

### 7.3 创建桌面池

创建前必须预检：

- 模板版本有效且已发布。
- 目标节点、存储和网络可用。
- 预计磁盘、内存和 VMID 数量充足。
- 存储是否支持链接克隆和快照。
- 当前是否存在冲突任务。
- 并发限制是否允许启动本批次。

支持：

- 链接克隆：创建快，但依赖模板和存储能力。
- 完整克隆：占用更多空间，但隔离和迁移能力更强。

克隆策略必须由桌面池显式保存，不能根据环境静默切换。

### 7.4 课程场次

课程状态：

~~~text
DRAFT → PREPARING → READY → OPENING → ACTIVE → CLOSING → CLOSED → ARCHIVED
~~~

课前准备：

1. 检查终端在线、桌面存在、模板版本、资源容量和冲突任务。
2. 根据策略执行终端唤醒、桌面还原和分波次预启动。
3. 检查 VM 状态、Guest Agent、网络和远程桌面端口。
4. 对异常座位给出原因，并允许排除后继续。

开课后：

- Broker 为每个座位或学生选择桌面。
- 签发短期、一次性、目标受限的连接授权。
- 教师能看到座位级状态和失败原因。

下课时：

- 先撤销或结束远程会话。
- 默认请求优雅关机。
- 根据桌面池策略保留、回滚或重新创建桌面。
- 取消任务不代表撤销已经完成的单机操作。

### 7.5 桌面持久化与还原

每个 DesktopPool 必须选择一种策略：

- **RECREATE**：下课后删除并从指定模板版本重建。推荐作为无状态教室默认方案。
- **ROLLBACK_BASELINE**：回滚到基线快照；必须确认存储支持且空间充足。
- **PERSISTENT**：保留桌面，不自动还原，适合长期个人桌面。

用户资料不能只存在于会被还原的系统盘。需要保留时使用独立数据盘、漫游配置或网络家目录。

必须区分：

- 快照回滚。
- 从模板重新创建。
- 从 PBS 备份恢复。

界面和 API 不得将三者模糊成同一个“还原”动作。

### 7.6 瘦客户机

- 首次启动通过一次性注册码注册。
- 注册后使用设备证书或等价设备身份，不长期依赖 MAC 地址。
- 上报设备 UUID、架构、Agent 版本、IP、硬件摘要、当前会话和心跳。
- 支持固定座位绑定和设备更换后的重新绑定。
- 本地不保存 PVE Token、模板权限或长期管理员密码。
- Launcher 支持全屏 kiosk、断线重连和课程结束后返回登录页。
- 学生网络、桌面网络、网关网络和 PVE 管理网络必须隔离。

## 8. 远程桌面策略

采用可插拔 Desktop Broker 和 Gateway，不把 PVE noVNC 当作日常学生 VDI。

推荐顺序：

1. **原生 RDP / FreeRDP**：受控瘦客户机的默认方向，适合局域网和低资源终端。
2. **Apache Guacamole + RDP**：浏览器零安装访问和兼容入口。
3. **PVE noVNC**：只用于安装、故障恢复和管理员应急控制台。
4. **SPICE**：作为 Linux、USB 重定向或特定场景的可选协议。

连接流程：

1. 终端以设备证书或用户身份登录平台。
2. Broker 根据课程、座位和当前分配确定目标桌面。
3. VM 未运行时创建启动任务。
4. 同时验证 PVE 状态、Guest Agent、网络和目标协议端口。
5. Broker 签发短期、一次性、只允许连接目标桌面的授权。
6. Gateway 建立会话，终端不接触 PVE 管理网和长期来宾凭据。
7. 下课、解绑或管理员撤销后，立即禁止新连接并终止已有授权。

网关策略必须可控制剪贴板、磁盘、打印机、USB 和音频重定向。

教师观察或控制学生屏幕必须单独授权、明确告知并记录审计。
